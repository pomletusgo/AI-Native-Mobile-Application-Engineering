## 2. 复刻边界

### 2.1 属于本次复刻范围（核心闭环）

```
名片夹/Home
  → 拍摄/导入名片
  → 名片区域检测与校正
  → OCR 文字识别
  → 联系人字段结构化
  → 人工校正
  → 保存名片
  → 查看详情

  → 重新打开（持久化）
```

用户注册、会员、订阅支付、广告、云同步、多设备同步、团队名片库、Salesforce/CRM 同步、企业权限与组织、数字名片设计/模板、QR 名片交换、Email Signature、Virtual Background、AI 企业情报/公司分析/财务分析/商务建议、会议录音/总结、销售漏斗。

在教师规定的功能边界、参考版本、设备环境与测试用例范围内，实现 **100% 可观察行为等价**，至少覆盖：

| 维度 | 含义 |
| --- | --- |
| UI 一致性 | 布局、文案、控件位置与层级可观察等价 |
| 交互一致性 | 手势、点击、返回、取消、重拍等操作路径一致 |
| 状态一致性 | 空/非空/加载/错误等状态转换一致 |
| 数据一致性 | 保存的字段、标签、备注内容一致 |
| 异常一致性 | 权限拒绝、取消、识别失败等异常路径一致 |
| 流程一致性 | 端到端流程步骤与顺序一致 |

### 3.3 AI/OCR 概率性的验收方式

- **确定性功能**（UI、导航、状态、保存、编辑、删除、搜索、标签、导出）：Reference Test Suite 100% 通过。
- **概率性功能**（OCR、姓名/公司/职位/电话/Email/地址识别）：
  1. 保存 AI/OCR 原始输出；
  2. 保存字段解析结果；
  3. 与 Ground Truth 比较；
  4. 计算字段级准确率；
  5. 与参考 App 结果比较；
  6. 分析错误原因；
  7. 允许用户人工校正。

> 关键原则：**AI 不允许「补全」名片上不存在的信息**。对于无法确认的字段必须返回 `nil`，不得根据语义凭空生成。

## 4. BusinessCard 数据模型（Schema）

### 4.1 顶层结构

```
BusinessCard
├── id                : UUID        // 主键
├── originalImageName : String?     // 原始名片图像标识
├── processedImageName: String?     // 校正/裁剪后图像标识
├── name              : String      // 姓名（唯一必填）
├── company           : String?     // 公司
├── jobTitle          : String?     // 职位
├── mobile            : String?     // 手机
├── phone             : String?     // 固话
├── fax               : String?     // 传真（可选）
├── email             : String?     // 邮箱
├── website           : String?     // 网站
├── address           : String?     // 地址
├── postalCode        : String?     // 邮编（可选）
├── department        : String?     // 部门（可选）
├── tags              : [String]    // 标签
├── notes             : String?     // 备注
└── createdAt         : Date        // 创建时间
```

### 4.2 字段规则

| 字段 | 必填 | 允许空 | 说明 |
| --- | --- | --- | --- |
| name | 是 | 否 | 空则不允许保存（见 T20） |
| company / jobTitle / mobile / phone / fax / email / website / address / postalCode / department | 否 | 是 | 缺失时必须为 `nil`，不得虚构 |
| tags | — | 是（空数组） | 去重、大小写不敏感 |
| notes | 否 | 是 | 任意文本 |
| createdAt | 是 | 否 | 保存时写入，不随编辑改变 |

### 4.3 字段抽取的歧义处理规则（Week4 实现，Week1 先约定）

| 场景 | 规格要求 |
| --- | --- |
| 字段歧义（如 `Apple`） | 无法确定归属时归入最可能字段；不可确定则 `nil`，不得多字段重复填充 |
| 人名 vs 公司（如 `Jordan Lee` / `Lee Consulting`） | 需结合版式与关键词判定，禁止将公司名识别为姓名（T08/TC07） |
| 多电话号码 | 必须区分 Mobile / Office(phone) / Fax，分别入对应字段 |
| 多 Email | 主邮箱入 `email`，其余按出现顺序保留，保存时写入 `notes`（实现见 `ExtractedCardFields.additionalEmails`；仅第一个占用 `email`，重复候选不重复收集） |
| 中英文混排 | 姓名字段保留原语言，不做翻译 |
| 字段缺失 | 返回 `nil`，禁止补全 |

## 6. 状态清单（State Inventory）

### 6.1 名片夹（P01）状态

| 状态 | 触发条件 | 表现 |
| --- | --- | --- |
| S1 空名片夹 | 无任何名片 | 显示空状态插图与引导文案「扫描第一张名片」 |
| S2 有名片 | 存在 ≥1 张名片 | 显示名片列表，每行含缩略信息 |
| S3 搜索中 | 搜索框有输入 | 列表按关键字过滤，无结果显示空结果提示 |
| S4 标签筛选 | 选中某标签 | 仅显示该标签名片 |

### 6.2 名片详情（P06）状态

| 状态 | 触发条件 | 表现 |
| --- | --- | --- |
| D1 查看 | 打开详情 | 展示全部已保存字段（空字段不显示或显示占位） |
| D2 编辑 | 点编辑 | 进入可编辑表单 |
| D3 字段可点击 | 电话/邮箱/网站 | 调用系统组件（tel: / mailto: / http:） |

### 6.3 全局状态与异常

| 状态 | 触发条件 | 表现 |
| --- | --- | --- |
| E1 相机权限拒绝 | 用户拒绝 | 提示并引导到设置，返回名片夹 |
| E2 相册权限拒绝 | 用户拒绝 | 提示并引导到设置 |
| E3 取消/返回 | 任意流程中途退出 | 不产生脏数据，返回上一级 |
| E4 识别失败 | OCR 无法识别 | 提示重试或手动录入 |
| E5 姓名为空 | 保存时 name 为空 | 阻止保存并提示 |

### 6.4 状态转换（核心闭环）

```
[空名片夹]
   │ 扫描 → 拍摄/导入 → 检测校正 → OCR → 结构化
   ↓
[确认页]──取消/返回──▶ [名片夹]（无脏数据）
   │ 确认保存
   ↓
[名片夹/有名片] ──▶ [详情] ──编辑/删除──▶ [名片夹]（列表更新）
   │
   └─ Kill App → Relaunch → [数据仍在] → [详情]（字段/标签/备注保持）
```

## 7. 测试名片数据集与 Ground Truth

- 建议 30–50 张，本仓库提供 30 张合成（虚拟）名片定义：`testcards/ground_truth.json`。
- 全部使用虚构人名、电话、Email、地址，避免真实敏感个人信息。
- 覆盖类型：中文名片、英文名片、中英双语、竖版/特殊布局、多电话/多 Email、字段缺失、拍摄质量较差、复杂 Logo/背景。

### 7.1 数据字段

每张名片定义包含：

| 字段 | 说明 |
| --- | --- |
| `id` | 测试名片编号（TC01…） |
| `categories` | 所属分类标签 |
| `layout` | `horizontal` / `vertical` / `bilingual` 等 |
| `quality` | `good` / `tilted` / `darkBg` / `shadow` / `complexBg` 等 |
| `groundTruth` | 标准答案字段（name/company/jobTitle/mobile/phone/fax/email/website/address） |
| `expectedAbsent` | 明确**不存在**的字段（用于验证「不得虚构」）；部分名片另含 `additionalEmails` |

### 7.2 评价指标

- 字段级准确率 = 正确字段数 / 有真值字段数（按字段分别统计）。
- 关键指标：`name` 准确率、`company` 准确率、缺失字段误报率（必须为 0）。

## 附录 A：工程打开、构建与测试

工程文件 `CamCardClone.xcodeproj` 已纳入版本库，可直接用 Xcode 打开，无需任何生成器。

```bash
# 1) 打开工程（macOS）
open CamCardClone.xcodeproj

# 2) 运行：选择 Scheme `CamCardClone` → 任意 iPhone 模拟器（iOS 17+）→ Run

# 3) 单元测试：Cmd + U，或命令行
xcodebuild test -project CamCardClone.xcodeproj -scheme CamCardClone \
  -destination 'platform=iOS Simulator,name=iPhone 15'

# 4) 仅编译（不做真机签名）
xcodebuild -project CamCardClone.xcodeproj -scheme CamCardClone \
  -configuration Debug -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath DerivedData CODE_SIGNING_ALLOWED=NO build-for-testing
```

工程由两个 Target 组成：`CamCardClone`（应用）与 `CamCardCloneTests`（单元测试，宿主为应用）。
`project.pbxproj` 使用 `objectVersion = 56`、`compatibilityVersion = "Xcode 14.0"`，
配置为自动生成 Info.plist（`GENERATE_INFOPLIST_FILE = YES`），并通过 `INFOPLIST_KEY_*`
声明相机、相册、通讯录的用途说明。

规范校验（需要 Node 环境）：

```bash
npm install
npm run spec:validate   # openspec validate --all --strict
```

> 交付物在 Windows 上生成，本机无 Xcode 与模拟器，因此编译、单元测试与 UI 验收的真实结果
