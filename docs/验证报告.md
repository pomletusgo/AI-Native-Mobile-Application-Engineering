## 说明

- 本工程为手工编写的 `project.pbxproj`（`objectVersion = 56`、`compatibilityVersion = "Xcode 14.0"`），与课程参考案例格式一致。结构检查证明引用自洽；该工程已在 GitHub Actions 的 `macos-15` runner 上真实编译并运行测试，这是比结构检查更强的证据，但仍不等同于在本机 Xcode 中打开、编辑与运行模拟器。
- 单元测试共 183 个方法（Model 9 / Repository 14 / CardHolderViewModel 10 / CardDetailViewModel 9 / PersistentBusinessCardRepository 16 / VCardExporter 19 / BusinessCardFieldParser 19 / FieldExtractionEvaluator 12 / OCRService 10 / CardBoundary 20 / ScanAccess 16 / ScanAuthorization 16 / CameraCapture 13）。UI Golden Test 的测试仍待 Week 5 补充；把相机取景、权限适配层与相册选择器接到扫描页上并替换占位，仍待 Week 3 后续补充。
- 字段抽取的 19 个规则测试用手写 OCR 文本作为夹具，验证的是「给定这段文本能否抽出正确字段」，**不等于**「真实名片图片经 OCR 后能否抽出正确字段」；后者要等 Week 3 的 OCR 接线后，用 `testcards/ground_truth.json` 跑字段级准确率才有结论，因此两者分开记录，未混为一谈。
- 字段级准确率与误报率的**数值**仍为「待执行」：数据集目前只有字段真值，缺少与之对应的 OCR 原文，任何数字都会是编造出来的。评价脚本已经就绪并通过自测，只等 OCR 原文补齐即可运行。
- 上述 CI 结论由公开 API 读到作业与步骤级状态（`OpenSpec Validate`、`Build for testing`、`Run unit tests` 均为 success）。精确的「Executed N tests」行需下载运行 artifact，而 artifact 下载需要仓库授权令牌，本机没有，故测试方法数以本地静态统计为准并已在表中注明口径。
- `ScannerEntryView` 仍是扫描入口占位，用模拟识别结果验证 T02/T12，不代表真实 OCR 已实现。Week 3 已交付 `OCRService` 与其失败路径、结果规范化（3.3 / 3.4）、名片区域检测与透视校正（3.2），以及相机取景与拍摄的实现（3.1 第三段：`AVCapturePhotoCapturer` 与 `CameraPreviewView`）；但扫描页尚未接线，因此这几项都还没有端到端的界面验收。
- 3.1 正在分段推进，已完成其中**不依赖真机的三段**：① `ScanAccess` 把「相机/相册授权状态 → 继续 / 请求授权 / 提示并跳设置」与「取消、重拍不残留产物」做成纯逻辑并单测（run #16）；② `ScanAuthorization` 把 AVFoundation / Photos 的真实状态映射过来、把「查询 → 判断 → 按需申请 → 再判断」收成可单测的推进函数，`PhotoImport` 用 `PhotosPicker` 读取并规范化导入结果（run #20）；③ `CameraCapture` 把「查权限 → 按需申请 → 拍摄」与三种拍摄失败收成可单测的编排，`AVCapturePhotoCapturer` + `CameraPreviewView` 提供真实取景与拍照（run #22）。**仍未开始**：把这三段接到扫描页上并替换 `ScannerEntryView`；相机实拍画面、系统权限弹窗与相册选择器的真实行为属人工验收，因此 T04（拍摄）与 T02/T05 的端到端仍为「待执行」。
- 3.2 的方向校正**只做透视摆正**，不依据长宽比自动转 90°：竖版名片本身合法，仅凭四边形比例无法区分「竖版名片」与「照片方向不对」，误转会直接破坏识别。图像方向留待 3.1 拍摄/导入阶段提供的方向信息处理，识别结果不理想时由用户重拍或手动调整——规格原文是「进行方向**或**透视校正」，透视校正已满足该项。
- `isReliable()` 的面积与长宽比阈值（0.12 / 0.98 / 1.15…3.6）是常见名片比例下的初值，尚未在真实照片上复核，等拿到真机与真实名片图片后需要重新标定并在表中更新结论。
- 5.3 只有 VCF 文本生成经过验证；写入系统联系人的 `Contacts` 接入与外发确认 UI 尚未实现，`T19` 的端到端验收未完成。
- 概率性功能（OCR、字段抽取）不使用「通过/失败」结论，而是以 `testcards/ground_truth.json` 统计字段级准确率与缺失字段误报率。
