## Context
`BusinessCardFieldParser` 是对 OCR 原文做结构化抽取的规则引擎：逐段判定，「先命中者先占位」。当前判定顺序为「邮箱 → 网址 → 标签 → 邮编 → 电话 → 地址（强特征）→ 公司（后缀）→ 地址（弱特征）→ 部门 → 职位 → 姓名」，其中地址强特征与公司后缀都用**子串**匹配。

2026-11-01 的实测把三类规则缺陷暴露出来：子串匹配使公司名被地址特征抢走（`工作室` 命中 `室`、`Dark Tower Studios` 命中 `tower`）；电话号码在形态不足以判定时兜底判为手机；职位依赖 23 个词的封闭词表。本变更只改这三处规则，不动数据契约与评价口径。

## Goals / Non-Goals
**目标**：让错误明细里的「字段归属错」与「职位召回缺失」两类**归零**，使 4 处 `invented` 判定的成因消失；「无标签号码分类」修好 TC23 的固话 / 传真漏抽并把手机 / 固话错误由 6 条降到 4 条（TC07 / TC21 因数据集标注内部不一致保留，见 D2）；同时保持 `BusinessCard` / `BusinessCardRepository` / `ExtractedCardFields` 的接口与既有 344 个单测全绿。

**非目标**：不改 OCR、不做残缺标签的猜测补全、不调评价口径、不动 Ground Truth、不承诺整体正确率阈值、不覆盖长尾职业。

## Decisions
### D1. 公司 / 地址由「命中顺序」改为「特征竞争」
单纯把公司提到地址之前会把「张江高科技园区」这类**地址里含行业词**的段判成公司，反向制造新的虚构，因此不采用调序，改为对**同时命中**的段做形态裁决：

1. 段内含门牌号类数字（`\d+号 / \d+楼 / \d+F`）或行政区划词（省 / 市 / 区 / 县 / District / City）→ **地址**；
2. 否则若公司后缀出现在**段尾**（`…有限公司` / `…工作室` / `…Studios`）→ **公司**；
3. 两者都无证据时**不判定**（返回 `nil`），继续下渗到部门 / 姓名，而不是默认塞进地址——否则 `Apple` 这类无后缀的单个西文词会被判成地址，制造新的虚构。

按此规则复算：`蓝海设计工作室`（后缀在段尾、无门牌号）→ 公司；`Dark Tower Studios`（`Studios` 在段尾）→ 公司；`上海市静安区南京西路500号`（含数字与区划词）→ 地址；`张江高科技园区`（`科技` 不在段尾，地址特征在段尾）→ 地址。**单字级地址特征（室 / 号 / 楼 / 层…）不再在整词内部生效**——`工作室` / `写字楼` 这类复合词按整词处理。

### D2. 无标签号码：形态优先，形态判不出则按空槽位落位
删除 `phoneTargetWithoutLabel` 末尾的 `return (.mobile, value)` 兜底，改为「形态 + 空槽位」两级判定。函数新增 `fields:` 参数以读取当前已占用的槽位：

| 形态 | 归属 |
|---|---|
| 段首标签命中（手机 / 固话 / 传真 / Tel / Fax…） | 按标签，形态仅作校验 |
| `+86` 前缀且位数 ≥ 13 | 手机 |
| 首位为 `0` | 固话 |
| ≥ 11 位数字 | 手机 |
| 形态判不出（如 `+1` 等其它国际区号且位数不足） | 按「手机 → 固话 → 传真」填入第一个**空槽位** |

形态能给出结论时若目标槽位**已被占用**，则返回 `nil` 不下判——**宁漏不假**，不把手机号改写到固话。形态判不出时按空槽位顺序落位，使同一张卡上的多个无标签号码各占一个槽位（TC23 的 `+1-555-0923 / 0924 / 0925` 依次进 手机 / 固话 / 传真）。

`13800000001` 归手机；`0755-1234567` 归固话。

**已知残留（不修）**：`+1-555-0307` 这类「其它国际区号 + 位数不足」的号码，TC07 / TC21 的真值标为固话，而同形态在 TC02 / TC06 / TC10 / TC13 / TC17 的真值标为**手机**——`ground_truth.json` 内部标注不一致，任何基于号码形态的规则都无法同时满足。按「不动数据、记残留」的决定，TC07 / TC21 的 4 条错例作为**数据集标注内部不一致**保留，手机 / 固话错误由 6 条降为 4 条，该类**不归零**。

### D3. 职位判定改为「后缀形态 + 通用职务词」双路
- **形态路**：中文段以常见职务后缀结尾（师 / 员 / 长 / 监 / 理 / 士 / 教练 / 主任 / 总监…）、长度 2–6 字、不含数字与地址特征；
- **词表路**：在既有 23 词基础上补入通用职务词（教师 / 医师 / 律师 / 会计师 / 工程师 / 导演 / 编导 / 店长 / 导游 / 技师 / 教练 / 司机…）与西文职务词（producer / scientist / editor / chef / nurse…），并把匹配由子串改为**整词**（避免 `Technical` 这类碎片命中）。

保留既有防线：整段既无后缀证据、也无词表命中时，不得判为职位（防止把 `专业可靠` 这类标语塞进职位）。

### D4. 过拟合防线
规则必须写成**可外推的形态特征**，不得逐条匹配 30 张语料里的字符串；每条新规则都要有**语料外**构造样例的单测（如「摄影师」「调度员」「+44-20-7946-0958」）。仅靠语料数字变好不足以判定完成——`proposal.md` 的判据是「按类别归零 **且** 单测覆盖通用规则」。

### D5. 独立变更 + 归档顺序
本次不并入 `replicate-camcard-core-slice`：那个变更是「复刻核心闭环」的交付契约，验收判据是确定性与概率性指标的实测值；本变更是「按实测归因修规则」。两者混在一轮会让「复刻完成度」与「规则优化」互相污染证据。

## Risks / Trade-offs
- **收紧规则可能改坏原本正确的抽取**：例如把某些地址行判成公司。缓解：既有 `BusinessCardFieldParserTests` 22 个方法与全量 344 个单测是硬回归面，每改一处都要重跑；语料上逐条比对错误明细而不是只看总数。
- **「形态优先 + 空槽位」仍可能降召回**：形态能判出但目标槽位已被占用时返回 `nil`（宁漏不假），比原来「无条件填手机」少了一个错填的手机；这是刻意的取舍，须在台账里写清，不得事后当作缺陷。
- **电话类的三类错例不归零**：TC07 / TC21 的 4 条错例源自 `ground_truth.json` 自身标注不一致（同形态号码在不同卡上分别标手机与固话），已按「不动数据、记残留」的决定保留，须在台账中写明这是**数据集问题**而非规则缺陷。
- **职位仍是词表 + 后缀**：长尾职业覆盖不到，属能力边界；不得为了让语料数字归零而把语料里的词逐条塞进词表（D4 的防线）。
- **本机读不回 CI 报告**：注解端点可用但需要分块。缓解：`ios` 作业复用 `DETECTCORPUS` 的做法，给字段级报告加同样的分块注解通道。
- **合成图偏乐观**：结论只适用于渲染图上的字段抽取，真实照片仍未复核（M18）。
